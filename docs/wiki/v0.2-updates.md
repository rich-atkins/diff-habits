# diff-habits v0.2 — evidence floors, a named refusal, and a boundary fix

v0.2 changes no metric definitions. It changes what the tool is willing to say on
thin data, makes its refusals precise, and fixes a window-boundary bug the new
self-test caught during development.

## 1. Evidence floor (fail closed on thin data)

Masking events are rare — published densities run roughly 0.2–4 per 1k added
lines — so a per-1k rate computed over a couple of hundred lines is noise wearing
a number's clothes. v0.2 adds one floor:

| Floor | Default | Governs |
|---|---|---|
| `--min-evidence-lines` | 500 | both masking rates and both duplication rates |

Below it, the report prints `insufficient (n=120 added lines, need >=500)` in
place of the rate. Raw counts stay visible so the reader sees why. JSON gains a
sibling `insufficient` map; numeric fields stay numeric.

## 2. `compare` refuses precisely

v0.1 aborted an empty-window compare with a generic `error:` before even
collecting the second window. v0.2 collects both windows, then refuses with the
empty window **named** (`comparison refused: the 'before' window has no added
lines…`), exit 1. Per-metric, deltas whose rate is below the floor in either
window print `insufficient evidence in <side>` instead of a percentage.

## 3. The boundary fix (found by the self-test)

A commit at exactly the split instant was previously mis-windowed. The suspected
bug was double-counting; the sabotage suite's boundary test showed the truth was
subtler — git's `--until` is inclusive while `--since` is exclusive, and the
first fix attempt dropped the boundary commit from BOTH windows. v0.2 anchors
both window edges at split−1s, so a boundary commit lands exactly once, in
*after*, matching git-habits' `>= split` convention. The test pins all three
behaviours (not lost, not doubled, same side as the sibling tool).

That sequence — plausible fix, test proves it wrong, corrected fix pinned — is
the whole argument for the self-test.

## 4. The sabotage self-test

The suite now builds **real git repositories** every run:

- **PLANTED** — silent `except: pass` swallows appear in added code after
  2026-04-13; the hard-masking rate must jump from 0 to >50 per 1k.
- **CONTROL** — clean throughout; the tool must stay quiet.

Both directions asserted: a detector that always fires is as broken as one that
never does. Run it: `pytest tests/test_sabotage.py -v`.

## Compatibility

- Exit codes: empty-window compare returns 1 with a named refusal (previously 2
  with a generic error).
- Window edges: a commit at the exact split instant now counts once, in `after`
  (previously in `before`). Splits at midnight between active days are unaffected.
- JSON: new `insufficient` key; existing keys unchanged.
