# diff-habits v0.1 — what it measures, and how to read it

diff-habits is the content-reading sibling of git-habits: it walks `git log -p` **added lines** and counts constructs that git metadata cannot see. It depends on git-habits as a library (sharing its exclusion rules) rather than forking it, so git-habits keeps its provable "never reads your source" guarantee while this tool deliberately crosses that line — locally only, emitting aggregates, never content.

## Commands

| Command | Question it answers |
|---|---|
| `scan` | how much error-masking is in the added code of this selection? |
| `compare --split <date>` | did masking density change either side of a date? |

## Metrics and their denominators

| Metric | Denominator | What it suggests |
|---|---|---|
| error masking (hard) per-1k | added lines | code that *hides* failure: silent catch/except swallows, lint/type suppressions, `as any` casts, stubbed returns |
| error masking (soft) per-1k | added lines | constructs legitimate often enough to report separately: optional chains, nullish defaults, TODO markers |
| top patterns | counts | which specific constructs drive the totals |
| duplication (per-million / % of meaningful) | added / meaningful lines | **experimental, flag-gated** — see below |

The hard/soft split is the honesty mechanism: a headline that counted `?.` as masking would be indefensible, so it isn't in the headline.

## Design positions (v0.1)

- **Regexes, not a parser.** They over-count and under-count; the *trend* between two periods is meaningful, the absolute number is an indicator. Stated in the output, not just the docs.
- **Duplication is off by default** behind `--experimental-duplication`, with a shouty caveat when shown: the v0.1 sequence-based method conflates copy/paste with re-added code and boilerplate and reads ~1000x above published research. Shipping one correct metric beats two where one is broken.
- **Line-level move detection is deliberately not measured** — it is a similarity-matching problem, and an approximation would produce numbers incomparable with the published research people would inevitably compare against.
- Domain dominates masking density: you cannot compare error-handling density across different problem domains and attribute the difference to authorship. Within-repo before/after is the only design this tool endorses.
